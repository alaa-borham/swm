# دليل التشغيل والنسخ الاحتياطي والاستعادة

## 1. المتطلبات

- خادم Linux أو Windows عليه Node.js 20 أو أحدث (يُفضّل 22 LTS).
- مساحة قرص للبيانات والنسخ (البداية: 1 جيجابايت تكفي لسنوات لمؤسسة متوسطة؛ تُراجع حسب حجم البيانات).
- اتصال الأجهزة بالخادم عبر الشبكة المحلية أو الإنترنت. العمل دون اتصال بالخادم غير مشمول في النسخة الأولى.

## 2. التثبيت

```bash
git clone <المستودع> food-system && cd food-system
npm ci --omit=dev
cp .env.example .env      # عدّل القيم
node --env-file=.env src/server.js
```

عند أول تشغيل يُنشأ المستخدم `admin`. إذا لم تحدد `ADMIN_PASSWORD` تُطبع كلمة مرور مؤقتة في الطرفية، ويُطلب تغييرها بعد الدخول.

### خدمة دائمة على Linux (systemd)

```ini
# /etc/systemd/system/food-system.service
[Unit]
Description=Food Retail System
After=network.target

[Service]
WorkingDirectory=/opt/food-system
EnvironmentFile=/opt/food-system/.env
ExecStart=/usr/bin/node src/server.js
Restart=always
User=foodsys

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now food-system
```

### HTTPS

عند الوصول عبر الإنترنت يجب التشغيل خلف وكيل عكسي بشهادة (مثل nginx مع Let's Encrypt) وضبط `COOKIE_SECURE=1` و`TRUST_PROXY=1`:

```nginx
server {
  listen 443 ssl;
  server_name erp.example.com;
  # ssl_certificate ... ; ssl_certificate_key ... ;
  client_max_body_size 10m;
  location / { proxy_pass http://127.0.0.1:3000; proxy_set_header X-Forwarded-For $remote_addr; proxy_set_header X-Forwarded-Proto https; proxy_set_header Host $host; }
}
```

في الشبكة المحلية فقط يمكن التشغيل مباشرة على المنفذ 3000 مع `COOKIE_SECURE=0`.

## 3. الحماية المطبقة

- كلمات المرور مخزنة بتجزئة scrypt مع ملح عشوائي، ولا تُخزن كنص.
- جلسات آمنة: كوكي HttpOnly وSameSite=Strict، انتهاء عند الخمول، وتسجيل خروج يلغي الجلسة في الخادم.
- تحديد محاولات الدخول: 5 محاولات خاطئة ← إيقاف 15 دقيقة.
- فحص الصلاحيات في الخادم لكل عملية، وتقييد المندوب بعملائه ومخزونه.
- حماية الطلبات: رأس مخصص إلزامي للعمليات المغيرة، وسياسة أمان المحتوى (CSP)، ومنع التأطير.
- المرفقات: PDF وPNG وJPEG وWEBP فقط، حتى 5 ميجابايت، مع فحص توقيع الملف، وتُحفظ خارج مجلد الواجهة بأسماء عشوائية ولا تُنفذ.
- رسائل الأخطاء للمستخدم لا تكشف بيانات داخلية، والسجلات تحمل رقمًا مرجعيًا دون بيانات العملاء.
- سجل التدقيق والقيود وحركات المخزون محمية من التعديل والحذف على مستوى قاعدة البيانات.

## 4. النسخ الاحتياطي

- **تلقائي يوميًا** بعد الساعة المحددة في الإعدادات (الافتراضي 23)، ويشمل قاعدة البيانات والمرفقات، مع الاحتفاظ بآخر 30 نسخة.
- **يدوي**: من شاشة «النسخ الاحتياطي» أو بالأمر `npm run backup`.
- مكان النسخ: `DATA_DIR/backups/backup-<التاريخ>-<auto|manual>/` ويحتوي `data.db` و`uploads/` و`manifest.json` (الأعداد والأرصدة وقت النسخ).
- فشل النسخ التلقائي يُسجل في سجل التدقيق بعملية `backup.failed` ويظهر في سجل الخادم.

**مهم:** النسخ على نفس الخادم لا تحمي من تلف القرص. انسخ مجلد `backups` يوميًا إلى مكان آخر (قرص خارجي، تخزين سحابي، أو خادم ثانٍ)، مثلًا:

```bash
rsync -a /opt/food-system/data/backups/ backup-host:/srv/food-backups/
```

ويحصر تنزيل النسخ واستعادتها في أصحاب صلاحية «النسخ الاحتياطي والاستعادة».

### نقطة الاسترجاع المقبولة

النسخة اليومية تعني أن أقصى فقد محتمل هو عمليات اليوم منذ آخر نسخة. إن كانت المؤسسة لا تقبل ذلك، تُرفع الوتيرة بجدولة `npm run backup` كل ساعة (cron) أو نسخ ملف القاعدة المستمر، ويُحدد ذلك قبل التشغيل.

## 5. اختبار الاسترجاع (بيئة منفصلة)

```bash
npm run verify-backup                 # أحدث نسخة
npm run verify-backup -- <اسم النسخة>
```

أو زر «اختبار الاسترجاع» في الشاشة. يُنسخ ملف النسخة إلى مجلد مؤقت منفصل، ويُفحص سلامته، وتُطابق أعداد المستندات والبنود والقيود وحركات المخزون والدفعات والأطراف والمرفقات وإجمالي المدين والدائن ورصيد المخزون وقيمته مع البيان المحفوظ وقت النسخ. يُنصح بتنفيذه شهريًا وتسجيل نتيجته.

## 6. الاستعادة

1. أوقف الخادم: `sudo systemctl stop food-system`.
2. اعرض النسخ: `npm run restore`.
3. استعد: `npm run restore -- backup-20261002-230000-auto`.
   - يتحقق الأمر من النسخة أولًا ولا يستبدل شيئًا إن لم تجتز التحقق.
   - تُحفظ القاعدة الحالية بجانبها باسم `data.db.before-restore-<الوقت>`.
4. شغّل الخادم وتحقق من آخر المستندات والأرصدة.
5. أي عمليات تمت بعد وقت النسخة يجب إعادة إدخالها.

## 7. نسيان كلمة مرور المدير

```bash
npm run reset-admin -- NewPass123
```

يُسجل ذلك في سجل التدقيق ويُطلب تغيير كلمة المرور بعد الدخول.

## 8. التحديث

```bash
npm run backup
git pull && npm ci --omit=dev
npm test
sudo systemctl restart food-system
```

## 9. المراقبة

- سجل الخادم: `journalctl -u food-system -f`.
- الأخطاء غير المتوقعة تظهر للمستخدم برقم مرجعي يطابق سطرًا في سجل الخادم.
- راجع دوريًا: النسخ اليومية في الشاشة، والمحاولات المرفوضة في سجل التدقيق.
